# config/ — everything that is *yours*

This directory is the seam between the public project and your private instance.
Everything here is **gitignored except the `*.example.*` templates and this file**, so
you can fork, run, and even publish your own copy without ever deciding what to scrub.

| File | Committed? | What it is |
|---|---|---|
| `taste.md` | **no** | The taste profile — tiers, geography rings, what counts as news. The ICP equivalent, and the source of the agent's judgment. |
| `sources.md` | **no** | The hand-maintained source registry — venues, promoters, listers, and standing negative findings. |
| `roster.json` | **no** | The roster in structured form: band, tier, lineup qualifier, no-surface flag. |
| `*.example.*` | yes | Templates for the three above. Filled with `<placeholders>` and the reasoning behind each section. |

## Getting started

```
npm run init-config     # copies every *.example.* to its real filename, never overwrites
```

Then edit the three files. `taste.md` matters most — it is injected verbatim into every
sweep's system prompt, and a vague one produces a firehose of shows you don't care about.

## The two halves of the roster

`taste.md` and `roster.json` describe the same bands in two forms on purpose:

- **`taste.md` is prose, for the model.** It carries the *why* — why a band is tier 1,
  what would have to change, which names are ambiguous and what they get confused with.
  It goes into the system prompt.
- **`roster.json` is structured, for the tooling.** It carries the *what* — name, tier,
  qualifier, no-surface. `npm run seed-board` reads it to create the initial band rows.

Keep them in sync. Once the board is deployed, **the board becomes the system of record**
for the roster and you curate tiers in its UI; `roster.json` is the seed, not a second
live copy.

## After editing

```
npm run update          # re-bakes taste.md + sources.md into both agent prompts
```

Agent system prompts are composed at push time (`src/lib/taste.ts`), so edits to these
files do nothing until you run `update`. Skills behave differently — agents reference
`version: "latest"`, so editing `skills/` and re-running `setup-skills` takes effect
without an agent version bump.

## What is deliberately *not* here

`.scene-radar.json` at the repo root holds provisioned Anthropic resource IDs (agent,
vault, memory store, environment). It is generated by `npm run setup` rather than
hand-edited, and it is gitignored for the same reason as this directory.
